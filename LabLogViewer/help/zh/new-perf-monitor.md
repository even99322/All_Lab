# 效能監看
> 即時顯示 LabLogViewer 是否卡頓、使用多少 CPU 與記憶體，以及介面忙於哪個函式的視窗。2.0 新增。

## 最短流程
1. **開啟。** **設定 → 外觀 → 進階 → 效能監看⋯** ![](new_perf_button.png)
2. **看三條曲線。** *介面延遲 (ms)* 是介面慢多少才回應（約 50 ms 以下就算順暢）、*CPU* 是單核心百分比、*記憶體* 是程式佔用的 MB。視窗開著時照常使用程式（開資料、切換 trace）。 ![](new_perf_window.png)
3. **找出慢在哪。** 「介面執行緒把時間花在哪裡」依占比排序函式；「最近的卡頓」列出每次 0.15 秒以上的凍結，含時間、持續時間與卡在哪裡。 ![](new_perf_stalls.png)
4. **留下紀錄。** **複製報告** 或 **儲存報告⋯**（存到資料夾的 `logs/performance-<時間>.txt`），可寄給開發者。**暫停** 凍結曲線，**重設** 重新開始。

## 結果代表什麼
- 延遲一直接近 0 且沒有卡頓：介面正常；覺得慢的動作是背景工作。
- 每次開關同一個檔案記憶體都上升且不再持平，代表有東西沒有釋放；請寄報告。
- 卡頓時占時間最多的函式就是該查的地方；監看只觀察，不會改變任何東西。

## 選項與參數
- 每秒取樣約 25 次，對速度的影響可忽略。關閉視窗就停止顯示。

## 做不出來時
- **一開始是空的**：曲線需要幾秒才會填滿。
- **記憶體顯示 0**：作業系統沒有提供這個數值；其他曲線仍可使用。
