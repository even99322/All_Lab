# Lab Control 1.0.33

- 發佈日期：2026-11-09
- 類型：新功能（Hub 各埠流量監控與限流、VPN 串流壓縮與省流模式、儀器改名全面同步、Yokogawa 量程）
- 前一版：1.0.32

## 摘要（貼到版本說明）

- **Hub「網路用量」新增「Hub 流量（各埠 × 資料類型）」**：每個連到 Hub 的請求（8765 網站與 API、8443 內網 https、
  8444 論文庫 https）都記下從哪裡來（區網 / VPN / NAS 本機轉入 / 外網）、哪一類（即時量測、數據檔、安裝與更新、
  狀態與指令、網頁、其他 API、論文庫）、收送多少，今天 / 本月 / 目前速度一目了然。
- **分類限流（站長）**：每一類可以設速度上限（KB/s，同一類共用）與每日上限（MB；超過回「流量已達上限」，隔天恢復），
  範圍選「區網以外」或「全部」。網路用量頁與登入永遠不擋。
- **經 VPN 的串流壓縮**：區網以外的 JSON / 網頁回應自動 gzip；Lab Control 遠端看即時量測的曲線改用「位元組重排＋zlib」
  無損壓縮；量測電腦經 VPN 送到 Hub 的資料也壓縮；手機看即時量測時最後一條 trace 沒變就不重送。
- **省流模式**：今天的用量超過門檻（預設 60 GB；依據可選 Hub 對外、路由器整個網段、或取大的）自動切換：
  即時曲線只留約 0.1% 精度（|S21| 約 0.01 dB；存的檔案不受影響）＋最高壓縮，約只剩原本的 1/3；手機 trace 抽成 300 點。
  也可以手動開。
- **儀器改名一起改所有用到它的地方**：量測方案（LAB/schemes）、範本、專案範本（會送回 Hub，別台也拿到新名稱）、
  電源群組與 M1–M3 記憶、＋／－ 步進、即時數據的排法、VNA 接線，以及目前開著的方案。另一台電腦收到同步的改名也會一起改。
- **Yokogawa 量程**：連線時電流模式預設量程 200 mA（`server.yokogawa_current_range: 0.2`；`keep` = 不改；
  instruments.yaml `on_connect.range` 優先；輸出開著不切換只提醒）。儀器控制視窗的「源量程」改成下拉選單（列出這台
  可用的量程，也可以直接打）。

## 細節

- 「NAS 本機轉入」：從 NAS 自己或容器轉進來的連線。Synology 的 Tailscale 是 userspace 模式，VPN 直接連 100.x:8765
  會算在這裡；經 tailscale serve（https 8443）進來的看 X-Forwarded-For 算 VPN。如果區網電腦也出現在「NAS 本機轉入」，
  代表 NAS 的 Docker 看不到真正的來源 IP，請把「本機轉入算區網以外」關掉。
- 壓縮格式：`{"zre", "zim", "n"}` / `{"zf", "n"}`（float32 位元組重排後 zlib，base64）；只有送 `X-Labhub-Enc: zs`
  的用戶端（Lab Control 1.0.33 起）才會收到，舊版照舊。
- API：`GET /api/traffic?days=`、`PUT /api/traffic/config`（站長）。資料存在 Hub 的 `data/traffic.json`。
- 以前的數據檔、實驗記錄裡的儀器名稱不改（那是當時的紀錄）。

## 更新步驟

1. Hub 控制台更新到 1.0.33；「網路用量」看「Hub 流量」那一區，需要的話在「限流與壓縮設定」設上限與省流門檻。
2. Lab Control（兩台量測電腦與遠端電腦）更新到 1.0.33（App 內更新即可）。
