# Lab Control 0.0.18

- 發佈日期：2026-10-09
- 類型：一個網址、一個 App、一個控制台
- Python：3.12
- 前一版：0.0.17
- 發佈檔：
  - `LabControlHub_v0.0.18.zip`
  - `LabControl_v0.0.18.zip`
  - `LabControlMonitor_v0.0.18.zip`
  - `QELLauncher_v0.0.18.zip`（App 的 Python 版）
  - `QELPlatform_v0.0.18.zip`（App 原始碼，用來打包 .exe / .dmg）
  - `QELPlatform_NAS_v0.0.18.zip`（NAS 專案設定；不用重建專案）

## 摘要（貼到 Lab APP「版本說明」）

- **下載頁**：`http://<NAS>:8765/get` 不用登入，自動給這台電腦用的 Windows .exe 或 Mac .dmg。
  - 沒登入的人打開 `http://<NAS>:8765/` 會直接到這裡，所以只要告訴大家一個網址。
- **App「量子工程平台」**（原本的啟動器）改成以功能為主：
  - 「量測」：列出量測電腦（誰在量、進度），按「在這台量測」就用量測模塊連過去；也可以在這台電腦量測；
  - 「數據與論文」：跟之前一樣，可以選專案、開整個專案；
  - 「程式」：按「開啟」，第一次會自動下載，有新版自動更新；
  - 「論文庫」按鈕開論文庫原本的網址；
  - 自動更新、開機自動開啟、紀錄都收在「⚙ 設定」。
- **不用自己裝 Python**：打包版 App 內附 uv，第一次開某個功能時自動下載 Python 3.12 和套件，放在 `~/.qel/`。
- **量測電腦**：站長在量測電腦的 App 裡「⚙ 設定 → 這台是量測電腦」輸入名稱（例如 `LAB-A`），之後：
  - 量測模塊以量測節點一直開著，關掉或當掉會自動重新開啟；
  - 登入電腦時自動開啟 App；
  - 有新版時，等節點閒置才更新，量測中不會被打斷。
- **網頁控制台**（平台網頁 →「控制台」，只有站長看得到）：
  - 「發佈更新」：把 Hub、論文庫、量測、讀檔、Monitor、App 的 zip、.exe、.dmg 拖進來，按「全部發佈」；
  - Hub 和論文庫交給 NAS 控制代理更新，網頁顯示進度；Hub 重新啟動的那幾秒會自動等它回來；
  - 「系統狀態」：Hub、控制代理、論文庫、NAS 剩餘空間、量測電腦、數據數、登入人數；
  - 「量測電腦」：每台的狀態、誰在量、進度。
- 論文庫照舊用自己的網址（`:8080`），不受影響。

## 新增 / 變更

- Hub：
  - `GET /get`、`GET /get/info`、`GET /get/<版本>/<檔名>`：公開下載頁，只開放 App 本身；
  - 控制台 API `/api/platform/console/…`：上傳暫存、發佈、工作進度、系統狀態、量測電腦（只有站長）；
  - `LABHUB_AGENT_URL`：控制代理網址，預設 `http://labcontrol-hub-agent:8766`。
- Lab Control：
  - 沒有設定 Hub 時，沿用 App 的登入（`QEL_GATEWAY`、`QEL_TOKEN`）；
  - `LAB_CONTROL_HUB` 可以用逗號分隔多個網址；
  - `LAB_CONTROL_NODE_NAME`：量測節點名稱；
  - `--target <量測電腦>`：開啟後「執行於」直接選那台。
- App：
  - 新分頁「量測」、「⚙ 設定」；
  - 模塊用 uv 建立環境（Python 版本依模塊的 `.python-version`，預設 3.12），uv 不能用時改用電腦上的 Python；
  - 開機自動開啟：Windows 寫在登錄檔 Run，Mac 用 LaunchAgents，Linux 用 autostart；
  - 量測電腦的裝置 token 存在 `~/.qel/launcher.json`（只有自己能讀）。
- 平台網頁：
  - 新增「控制台」；
  - 「站長管理」改名「帳號與權限」，原本的模塊上傳表移到控制台。
- 打包：App 內附 uv，打包工具會自動安裝。
