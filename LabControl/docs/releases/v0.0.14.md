# Lab Control 0.0.14

- 發佈日期：2026-10-08
- 類型：發佈中心（Monitor）：把新版 zip 丟進來，一鍵更新所有模塊與網站
- Python：3.12
- 前一版：0.0.13
- 發佈檔：
  - `LabControl_v0.0.14.zip`
  - `LabControlHub_v0.0.14.zip`（**這版 Hub 要更新**，並且第一次要把論文庫資料夾掛給控制代理，見下方）
  - `LabControlMonitor_v0.0.14.zip`
  - `QELLauncher_v0.0.14.zip`（量子工程啟動器）

## 摘要（貼到 Lab APP「版本說明」）

- Monitor 新增「**發佈中心**」（第一個分頁）。之後更新任何東西都只要：把新版 zip 拖進來 →「▶ 全部發佈」。
  - 程式會自己判斷每個 zip 是哪個模塊、哪一版，並列出目前線上的版本。版本比目前舊時會先問。
  - 發佈說明從 zip 裡的版本說明自動帶入，可以修改。
- 各種 zip 會這樣處理：

  | zip | 做什麼 |
  |---|---|
  | Hub `LabControlHub_v*.zip` | 更新 NAS 上的 Hub 網站：停止 → 備份 → 換程式 → 重建 → 啟動 → 確認，失敗自動換回 |
  | 論文庫（paperlib 資料夾的 zip） | 更新論文庫網站：備份程式 → 換程式 → 建置映像 → 重建容器 → 啟動 → 確認版本，失敗自動換回。`data/`（論文、資料庫）、`import/`、`docker-compose.yml` 都不動 |
  | 量測模塊、讀檔模塊（LabLogViewer）、Monitor、啟動器 | 發佈到平台：各電腦的啟動器**自動更新**；量測節點也從 Hub 自動更新 |

  順序固定：論文庫 → 各模塊 → Hub。Hub 會重新啟動，所以放最後。
- 啟動器會自動更新模塊：
  - 每 5 分鐘檢查一次，有新版就安裝；
  - 模塊正在執行時，等它關閉後再更新；
  - 可以關掉「自動更新模塊」。
- 啟動器自己的新版：上方出現「更新啟動器」，按一下下載並重新開啟。
- 量測節點更新：Hub 的版本清單也包含發佈中心上傳的 Lab Control，不一定要經過 Lab APP。

## 第一次（只需要一次）：讓控制代理也能更新論文庫

Hub 控制代理要能讀寫論文庫的專案資料夾，並建置它的 Docker 映像：

1. 用 Monitor「Hub 控制台」或發佈中心，把 Hub 更新到 0.0.14。
2. 把 `LabControlHub_v0.0.14.zip` 裡的 `docker-compose.yml` 複製到 NAS 的 `LabControlHub` 資料夾，蓋掉舊的。
   如果你之前改過舊的 compose（例如 `/releases` 那行、論文庫網址），新檔也要做同樣的修改。
   確認 agent 服務的這一行指到論文庫專案資料夾，也就是有 `Dockerfile`、`app/`、`data/` 的那個：

   ```yaml
   - /volume1/docker/paperlib:/stacks/paperlib
   ```

   同時確認 `PAPERLIB_URL` 是論文庫的網址：`http://192.168.50.2:8080`。
   compose 裡的論文庫網址已經填好：
   - 內網 `http://192.168.50.2:8080`；
   - VPN `http://100.114.33.20:8080`。
   路徑 `/volume1/docker/paperlib` 對應的是和 `LabControlHub` 同一個 `docker` 共用資料夾裡的 `paperlib`。
3. 在 Container Manager → 專案 → LabControlHub →「建置」（或停止 → 清除 → 用同一個資料夾重新建立）。
4. 打開 Monitor →「發佈中心」，表格會顯示論文庫目前的版本。

沒有做這一步時，論文庫的 zip 會顯示「控制代理沒有設定論文庫」，其他 zip 照常發佈。

## 新增

- 論文庫連結依使用者連進 Hub 的位址自動選：`LABHUB_PAPERLIB_PUBLIC` 可以用逗號列出多個網址，例如
  `http://192.168.50.2:8080,http://100.114.33.20:8080`。在實驗室內網開到內網網址，用 VPN 開到 VPN 網址。
- `labhub/packages.py`：辨識發佈 zip。
  - 優先看 `qel-module.json`（`{id, version, name, notes}`）；
  - 沒有的話依內容判斷：`labcontrol/`、`labmonitor/`、`qel_launcher/`、只有 `labhub/`、`Dockerfile` ＋ `app/config.py VERSION`、LabLogViewer 的 `app/`；
  - 發佈說明取自 `docs/releases/v<版本>.md` 的摘要、LabLogViewer 的 `update.txt`，或 `CHANGELOG.md`。
- `tools/make_release.py`（Lab Control 與 QELPlatform 都是）：發佈 zip 裡加上 `qel-module.json`。
- 控制代理（`labhub/agent.py`）：
  - 論文庫的動作：`paperlib_update`、`paperlib_restart`、`paperlib_rollback`；
  - 用 Docker Engine API `POST /build` 建置映像，建置內容不含 `data/`、`import/`、`backups/`，並遵守 `.dockerignore`；
  - 用原本的容器設定（環境變數、掛載、網路、compose 標籤）重新建立容器；
  - 備份存在 `LabControlHub/backups/paperlib_v<版本>_<時間>.zip`，保留最近 10 份；
  - `GET /api/agent` 多了 `paperlib`（版本、容器狀態、備份）；
  - 新的環境變數：`PAPERLIB_DIR`、`PAPERLIB_CONTAINER`、`PAPERLIB_URL`、`PAPERLIB_VERIFY_S`。
- Hub：
  - `releases()` / `release_zip()` 也提供 `data/modules/labcontrol/<版本>/` 的 zip（去掉最外層資料夾），量測節點可以直接更新；
  - 模塊清單多了「量子工程啟動器」（`launcher`），平台網頁可以下載。
- Monitor：`labmonitor/publish_tab.py`（發佈中心）。
- 啟動器 0.0.14：
  - 自動更新模塊，設定存在 `~/.qel/launcher.json`；
  - 「檢查更新」按鈕；
  - 啟動器自我更新：Python 版本下載到 `~/.qel/modules/launcher/`，之後開啟時直接執行新版；打包版開啟下載頁。
