# Lab Control 0.0.15

- 發佈日期：2026-10-08
- 類型：NAS 改成「一個專案、三個容器」（論文庫、Hub、控制代理），支援論文庫的部分更新包
- Python：3.12
- 前一版：0.0.14
- 發佈檔：
  - `QELPlatform_NAS_v0.0.15.zip`（NAS 專案的 docker-compose.yml ＋ 安裝說明）
  - `LabControlHub_v0.0.15.zip`
  - `LabControl_v0.0.15.zip`
  - `LabControlMonitor_v0.0.15.zip`

## 摘要（貼到 Lab APP「版本說明」）

- NAS 上的論文庫、Hub、控制代理放進**同一個 Docker 專案** `qelplatform`，各自是獨立的容器：
  - `paperlib`
  - `labcontrol-hub`
  - `labcontrol-hub-agent`

  容器之間用名稱連線，Hub 用 `http://paperlib:8080` 連論文庫，不再出現「連不到論文庫 Connection refused」。
- 資料留在原本的資料夾：`docker/paperlib/data`、`docker/LabControlHub/data`。
- 發佈中心可以直接丟論文庫的**部分更新包**（例如 `paperlib_1.7.0_…_update.zip`，只有改過的 `app/` 檔案）：
  - 只覆蓋包裡的檔案；
  - 更新包需要的基底檔案缺少時（例如 1.7.0 需要 1.6.0 才有的 `projects.py`、`taxonomy.py`），在動任何東西前就拒絕。
- 論文庫更新的停機時間縮短：
  - 先換程式、建好新映像，這段時間舊版照常服務；
  - 然後停止 → 備份資料庫 → 啟動新版 → 確認版本；
  - 失敗時程式和資料庫都換回。

## 新增 / 變更

- `deploy/platform/docker-compose.yml`、`README.md`：一個專案的 NAS 設定與「從兩個專案改成一個」的步驟。
- `tools/make_release.py`：
  - 產生 `QELPlatform_NAS_v<版本>.zip`，內含 `qel-module.json`（kind `deploy`），丟進發佈中心會提示「不用發佈」；
  - Hub zip 不再附 `docker-compose.yml`。
- 控制代理：
  - 論文庫的完整包與部分更新包都能用；
  - 部分更新包會檢查 `from . import …` 需要的模組是否存在；
  - 停機後用 SQLite backup 備份 `data/library.db`（保留最近 5 份），失敗時換回；
  - 更新步驟：檢查 → 備份程式 → 換程式 → 建置映像 → 停止 → 備份資料庫 → 重建容器 → 啟動 → 確認版本。
- 發佈中心：辨識論文庫部分更新包（`app/config.py` 有 `PAPERLIB` 與 `VERSION`），發佈說明取自 `UPDATE_NOTES_*.md`。
- `deploy/hub/`：保留給只裝 Hub、沒有論文庫的情況。

## 測試

- `tests/test_publish.py`：
  - 部分更新包：缺基底檔案時拒絕且不動任何東西；成功時只覆蓋包裡的檔案；壞掉時程式與資料庫都換回；
  - 資料庫在停機後備份；
  - NAS 安裝包被發佈中心拒絕。
