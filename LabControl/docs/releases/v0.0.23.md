# Lab Control 0.0.23

- 發佈日期：2026-10-10
- 類型：修正（儀器歸屬）
- 前一版：0.0.22
- 發佈檔：`LabControl_v0.0.23.zip`；讀檔模塊更新包 `LabLogViewer_v2.1.1_patch.zip`

## 摘要（貼到 Lab APP「版本說明」）

- 修正：LAB-2 把 DC1、magnet_A、magnet_B 拖到 LAB-1 之後，DC1–DC4 和 magnet_A / magnet_B 仍列在「這台電腦」。
  - 原因：0.0.22 只認 App 量測電腦模式的節點名稱；用工具列「🛰 量測節點」開的節點（名稱存在 `LAB/node_state.json`）不算量測電腦，`node:` 沒有生效。
  - 現在量測節點一上線就套用 `node:`：別台的儀器中斷、移出，不回報 Hub，不用重開；
  - magnet 指定給 LAB-1 時，它的電源（沒寫 `node` 的 DC1–DC4）也一起算 LAB-1 的；
  - 其他電腦「執行於 LAB-2」時，LAB-2 的儀器清單也只有 LAB-2 自己的。
- 讀檔模塊 LabLogViewer 2.1.1（更新包）：以最新的 2.0 為基礎加上 `.nc` 讀取；`.nc` 的標籤、星號、註解寫在檔案裡；去背景支援 `.nc`。

## 變更

- `core/nodes.py`：這台的名稱多了 `LAB/node_state.json` 的節點名稱與執行中的節點；量測電腦判斷多了「節點執行中 / 自動上線 / `remote.node_enabled`」；虛擬儀器指定給別台時，它沒寫 `node` 的電源跟著。
- `core/station.py`：`apply_ownership()` 重新套用 `node:`（中斷、移出 / 載入）。
- `remote/node.py`：節點上線時登記名稱並套用；離線時取消。
- `remote/client.py`：控制端的節點鏡像只建立那個節點的儀器。
- 儀器伺服器：拖曳後立刻套用、更新 Hub 上的儀器清單。

## 測試

- `tests/test_ownership_ports.py` 新增 4 項（共 17 項）：用 LAB-2 實際的 instruments.yaml（拖過 DC1、magnet_A、magnet_B）
  - magnet 帶走電源；
  - `node_state.json` 的名稱讓這台成為量測電腦；
  - 節點上線後立刻移出、不回報 Hub；
  - 控制端鏡像只有 LAB-2 的儀器。
