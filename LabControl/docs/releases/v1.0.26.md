# Lab Control 1.0.26

- 發佈日期：2026-11-05
- 類型：修正（儀器伺服器「新增儀器」找不到 / 連不上 USB 儀器）
- 前一版：1.0.25

## 摘要（貼到版本說明）

- **新增儀器的 VISA 掃描與連線測試改成和實機驗證過的 GS210 連線程式同一套做法**：
  - 優先用 NI-VISA（`C:\Windows\System32\nivisa64.dll`）；系統預設的 VISA 被其他廠商（例如 R&S VISA）接手時，
    USB-TMC 儀器常常列不到或打不開。沒裝 NI-VISA 才退回系統預設 VISA，再退回 pyvisa-py。
  - 用 `list_resources("?*")` 列資源，只留 `::INSTR`（同一個位址只列一次）。
  - 開啟時等 3 秒鎖定（`open_timeout=3000`），先設 `\n` 寫入 / 讀取結束字元，再送 `*IDN?`。
- **USB 儀器即使 `*IDN?` 失敗也認得出來**：從位址解析 VID / PID / 序號，GS210（0x0B21 / 0x0039）直接建議 `yokogawa.gs200`。
- **核對序號**：USB 位址的序號和 `*IDN?` 回傳的序號不一致時，掃描與連線測試都會警告（避免連錯台）。
- 同型號多台時，清單逐台列出序號並提醒「請依序號選擇」；從掃描清單加入時，標籤預設為「型號 序號」。
- 連線測試顯示廠牌 / 型號 / 序號；失敗時提示檢查 USB-TMC 模式、USB 線和 NI-VISA，並標出實際用的 VISA 函式庫。
- 儀器連線（`VisaTransport`）也帶 `open_timeout=3000`。

## 設定

`server.visa_backend`：空白（預設）= 自動（NI-VISA → 系統預設 → pyvisa-py）；也可填 VISA dll 路徑或 `"@py"`。

## 細節

- `core/transport.py`：`visa_candidates`、`shared_resource_manager`（每種 backend 一個、依序嘗試）、`open_visa_resource`、
  `reset_resource_managers`。
- `diagnostics.py`：`parse_usb_address`、`suggest_drivers_usb`（driver 的 `USB_IDS`）、`identify_resource`、`probe_resource`；
  `Resource` 多了 vid / pid / serial / warning。
- Lab Monitor 版本號跟上 Lab Control（1.0.25 漏改）。
- tests/test_visa_scan.py（假的 pyvisa，不需要硬體）。

## 更新步驟

儀器電腦更新 Lab Control 1.0.26 後，在儀器伺服器「新增儀器 → 掃描 VISA 資源」即可。
