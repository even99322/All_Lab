# Lab Control 0.0.27

- 發佈日期：2026-10-11
- 類型：程式內更新推播、版本檢查、功能更新包（只更新程式碼）
- 前一版：0.0.26
- 發佈檔：
  - `LabControlHub_v0.0.27.zip`（**Hub 要更新**：推播 `/get/watch`、功能更新包資訊、LabLogViewer feed）；
  - `LabControl_v0.0.27.zip`（原始碼；也是之後的「功能更新包」）；
  - LabLogViewer 2.1.2 的 repo 檔案（`LabLogViewer_v2.1.2_repo_files.zip`）。

## 摘要（貼到版本說明）

- **更新推播**：
  - 站長在控制台發佈新版，幾秒內各電腦就會收到通知：
    - Lab Control：右下角跳出通知，有「立即更新 / 更新內容… / 稍後」；
    - LabLogViewer：鈴鐺與寵物通知。
  - 不用自己去網頁看，也不用再從瀏覽器下載（不會再看到 Edge 的「不常下載」）。
- **立即更新**：
  - Lab Control：下載後重新開啟；
  - LabLogViewer：下載安裝檔，安靜安裝後自動重開，保留安裝位置與圖示；
  - 量測中不會更新。
- **版本檢查**：
  - Lab Control 在「設定 ▾ → 版本檢查…」，可以看到：
    - 目前版本與程式本體；
    - Hub 上的最新版、更新方式、更新內容；
    - 推播開關、「重新檢查」、「立即更新」。
  - LabLogViewer 在「設定 → 關於 → 檢查更新」。
- **功能更新包**（Lab Control）：
  - 只改程式碼的新版只下載程式碼（約 1 MB），幾秒完成，`.exe` 不用換；
  - 需要新套件（`requirements.txt` 改了）時，才下載整個 `.exe` / `.dmg`。程式會自己判斷用哪一種。
- **安全網**：
  - 新版開不起來時，下次開啟自動退回上一個可用的版本，那一版之後不再使用；
  - 環境變數 `LABCONTROL_NO_OVERLAY=1` 只用 `.exe` 內附的版本。

## 第一次升到 0.0.27

0.0.26 還不認得功能更新包，所以這一次要發佈完整的程式。之後就只要發佈程式碼 zip。

1. 控制台發佈 `LabControlHub_v0.0.27.zip`，更新 Hub。
2. 打包並發佈 Lab Control 0.0.27：
   - Windows：`packaging/build_windows.bat` 產生 `LabControl_v0.0.27_windows.exe`；
   - Mac：`packaging/build_macos.command` 產生 `.dmg`。
3. LabLogViewer：
   - 把 `LabLogViewer_v2.1.2_repo_files.zip` 覆蓋到 repo，推 tag `v2.1.2`；
   - GitHub Actions 產生的 `.exe` / `.dmg` 拖進控制台發佈；
   - 已經裝了 2.1.1 的電腦要先手動裝一次 2.1.2，2.1.2 起才收得到推播。
4. 各電腦：
   - Lab Control 0.0.26 會在狀態列提示「⬆ 更新到 0.0.27」，按一下；
   - 沒有裝過的電腦，從下載頁 `/get` 安裝。

## 之後怎麼發佈新版

| 改了什麼 | 做什麼 | 使用者看到 |
|---|---|---|
| 只有程式碼（大部分的更新） | 改版本號 → `python tools/make_release.py` → 控制台發佈 `LabControl_v<版本>.zip` | 推播 → 立即更新（約 1 MB，幾秒） |
| `requirements.txt`（加套件、換版本） | 另外打包 `.exe` / `.dmg`，和 zip 一起發佈 | 推播 → 立即更新（整個程式） |
| 只上傳 zip，但 requirements 改了 | — | 「等站長上傳安裝檔」，不會裝不相容的程式碼 |
| LabLogViewer | GitHub Actions 打包 → 控制台發佈 `.exe` / `.dmg` | 鈴鐺推播 →「立即更新」 |

## 變更

- **Hub**
  - `labhub/appupdates.py`（新增）：
    - `GET /get/watch?app=&version=&wait=`：長輪詢，一發佈就回應（`wait` 最多 120 秒）；
    - `GET /get/info`：每個 app 多了 `code`（最新的 Python zip，含 `sha256`、`requirements` 指紋、`python`）、`installer_version`；
    - `GET /get/feed/lablogviewer.json`：LabLogViewer 的 feed 格式，加上 `downloads`。
  - `platform.add_release`：
    - 記錄每個檔的 sha256；
    - 發佈時喚醒等待中的推播。
  - `/get/<app>/<版本>/<檔名>`：功能更新包 zip 也不用登入。
- **Lab Control**
  - `main.py`（打包版入口）：
    - 載入 `~/.qel/labcontrol/code/<版本>/` 裡、執行環境相同的最新功能更新包；
    - 先試用新版，開不起來就退回；
    - 一開始就載入失敗時，改用內附的版本。
  - `labcontrol/selfupdate.py`：
    - `check()` / `plan_for()` 決定更新方式：功能更新包、整個程式、Python 版、或等待安裝檔；
    - `apply_code()`：檢查 sha256、版本號、requirements 指紋後才安裝，只保留最近 3 版；
    - `watch()` 負責長輪詢；
    - `mark_good()`。
  - `labcontrol/apps/qt/updates.py`：
    - 右下角的更新通知；
    - 「版本檢查」視窗；
    - 背景推播：長輪詢，連不到時 10 秒到 10 分鐘退避重試，另外每 30 分鐘檢查一次當備援；
    - 工作列提醒；
    - 推播開關寫在 `settings.yaml` 的 `app.check_updates`。
  - 量測節點的「請更新」與 `labcontrol update` 也會用功能更新包。
  - `packaging/build_app.py`：
    - 打包時寫入 `runtime.json`（版本、requirements 指紋、Python、平台）；
    - 把標準函式庫與常用子模組全部打包進去，讓之後的功能更新包可以用到。
- **LabLogViewer 2.1.2**
  - `app/core/hub_update.py`、`app/gui/hub_updates.py`：推播、立即更新、檢查更新；
  - `installer.iss`：安靜安裝時保留原本選的圖示。
- **測試**
  - `tests/test_standalone.py`：
    - 更新方式的判斷；
    - 功能更新包的安裝與拒絕；
    - 打包版入口的載入、退回、壞掉的更新包；
    - 通知、版本檢查視窗、推播迴圈。
  - `tests/test_console.py`：推播長輪詢、功能更新包資訊、LabLogViewer feed。
  - LabLogViewer `tests/test_v212_hub_update.py`：16 項。
