# Lab Control 0.0.9

- 發佈日期：2026-10-01
- 類型：功能版本（Hub 控制台、遠端直接控制 DC / VNA、即時監控、儀器伺服器群組、新外觀）
- Python：3.12
- 前一版：0.0.8
- 發佈檔：`LabControl_v0.0.9.zip`（Lab APP）、`LabControlMonitor_v0.0.9.zip`（Lab APP，新程式）、`LabControlHub_v0.0.9.zip`（NAS）

## 摘要（貼到 Lab APP「版本說明」）

- **Hub 控制台**：在 Monitor 或 `http://NAS:8766/` 選新版 Hub 的 zip，按「更新網站」就好。每一步都即時顯示：停止 → 備份 → 換程式 → 重建 → 啟動 → 確認版本；失敗會自動換回舊版。也有「完全重建」「重新啟動網站」「停止」「啟動」「回到這版」。
- **Lab Control Monitor 改用 Lab APP 發佈**（程式名稱 `LabControlMonitor`），不需要再產生 exe。
- **在一般電腦直接控制量測節點的 DC 與 VNA**：「執行於」選節點 A 後，就能命令 A 連線儀器，並在即時監控裡控制它的電源群組和 VNA。
- **右上改成分頁「即時監控 / 量測監控」**：
  - 即時監控可以開成獨立視窗；
  - 電源可以群組化：拖曳合併 / 拆開、M1–M3 記憶、兩台時的 ± 微調、合併時選「覆寫 / 平均」；
  - VNA 可以切換 S11 / S12 / S21 / S22、調參數、開關 RF、看曲線；
  - 開始量測時自動切到量測監控。
- **儀器參數**預設只顯示已連線儀器的參數。
- **儀器伺服器以群組顯示**：每台量測節點一個群組，另有「未歸屬」。儀器可以拖曳移動；每個群組都有「全部連線 / 全部斷線」。
- **新外觀**：深色、卡片、藍色主要按鈕，與 Lab APP 一致，深色為預設。
- Hub token 固定為 `Labqel330`，Lab Control 與 Monitor 已預設好。

## 新增

### Hub 控制台與控制代理（`labhub/agent.py`、`labhub/static/console.html`、`labmonitor/console.py`）

- NAS 上多一個容器 `labcontrol-hub-agent`（port 8766），透過 Docker Engine API 控制 `labcontrol-hub`。它只用 Python 標準函式庫。
- 可以執行的工作：

  | 按鈕 | 步驟 |
  |---|---|
  | 更新網站 | 檢查 zip → 停止 → 備份 → 換程式 → 重建 → 啟動 → 確認版本 |
  | 完全重建 | 重新下載 python 映像，然後重建 |
  | 重新啟動網站 | |
  | 停止 | |
  | 啟動 | |
  | 回到這版 | 從備份還原 |

- 更新時：
  - zip 不用解壓縮；zip 內 `labhub/` 在任何一層都可以；
  - 不是 Hub 的 zip，會在「停止」之前就拒絕；
  - 新版沒在時限內回應正確版本時，自動換回舊版，並加上「換回舊版 / 重建 / 啟動 / 確認」這幾步。
- 每一步的狀態與訊息都即時顯示（long-poll）。同一時間只能執行一個工作，別台電腦開始的工作也看得到。
- 備份存在 `LabControlHub/backups/labhub_v<版本>_<時間>.zip`。
- Monitor 的「Hub 控制台」分頁：
  - 顯示網站狀態、執行中版本、NAS 上的程式版本、控制代理版本；
  - 選 zip（或拖進來）、按鈕、步驟列、執行紀錄、備份清單；
  - 「用這個程式內附的 Hub」：不用下載 zip。
- 網頁版控制台 `http://NAS:8766/`（token 登入）也有同樣的功能。
- 0.0.8 的 Hub 自我更新（`data/hub_app`）改由控制台取代。第一次更新時，舊的自我更新紀錄會停用。

### 遠端直接控制 DC / VNA

- 本機與遠端節點用同一組後端（`labcontrol/remote/backend.py`：`LocalBackend` / `RemoteBackend`）。
  即時監控、儀器參數、儀器伺服器都透過這組後端操作，所以在 B 電腦操作 A 節點的儀器，就跟操作本機一樣。
- 節點新增指令：`sources`、`group_ramp`、`group_stop`、`ramp_status`、`fine_step`、`output`、`vnas`、`vna_catalog`、`vna_trace`、`add_instrument`。
  - 設定類的指令受 `remote.node.allow_remote_set` 限制；
  - 量測中讀 VNA 曲線會被拒絕。
- 電源群組斜坡（`labcontrol/core/grouping.py`）：
  - 成員輪流前進，彼此差距不超過一步；
  - 步進 = min(速率 × 0.1 s, 每台的 max_jump)；
  - 可以中止；目標值先檢查每台的上下限。

### 即時監控 / 量測監控分頁（`labcontrol/apps/qt/live/`）

- 主視窗右上改成「監控」卡片，有兩個分頁：即時監控、量測監控。還沒量測時可以自由切換；開始量測（本機或節點）時自動切到量測監控。
  量測進行中，即時監控只顯示數值，不能控制。
- 「⧉ 獨立視窗」：即時監控可以單獨開一個視窗，電源和 VNA 並排顯示；關掉視窗會放回分頁。
  放在主視窗時比較窄，電源和 VNA 改成兩個小分頁。
- **電源群組卡片**，操作方式跟實驗室的 Yokogawa 網頁面板一樣：
  - 拖曳成員（⠿）到別張卡片 = 合併，跟隨第一台（master）；拖到卡片之間的空隙 = 拆出來自己一組；
  - 合併時目前值不同，會問「覆寫（以 master 值）」或「平均」，然後整組慢慢斜坡過去；
  - 左邊 M1 / M2 / M3：
    - 點一下：以 0.05 mA/s 斜坡到記憶值（`live.memory_ramp_mA_s`）；
    - 還沒存過時，點一下 = 記住 master 目前值；
    - 右鍵：記住 / 清除；
  - 右邊 ＋ / －（只有剛好兩台時才有）：一次只動一台一個最小步進（＋ 動較低的那台，－ 動較高的），按住會連續；
  - 目標 + 速率 →「▶ 前往」、「■ 停止」、整組輸出開關；
  - 跟隨者的數值一直顯示；
  - 群組存在 `LAB/live_groups.json`，每台電腦 / 節點分開存；雙擊群組名稱可以改名；
  - 預設群組 = `instruments.yaml` 的虛擬雙電源（例如 magnet_A = DC3 + DC4）。
- **VNA**：
  - 選 VNA、RF 輸出開關；
  - S11 / S12 / S21 / S22 按鈕：ZNA 上沒有這條 trace 時自動建立；
  - 起訖頻率、中心 / 頻寬、點數、功率、IF 頻寬、平均次數（改了按 Enter 或「套用設定」）；
  - 單次或連續讀曲線；顯示振幅 dB、相位、實部、虛部。
- 只列出已連線的電源和 VNA；儀器連線或斷線後會自動更新清單。
- 「執行於」切到節點時，即時監控跟著換成那台的儀器。

### 儀器參數

- 新增「只顯示已連線」，預設勾選（`editor.channels.only_connected`）。取消勾選就能看到全部，用來拖進流程圖編輯方案。
- 電磁鐵組要它的電源都連線才會顯示。遠端節點的連線狀態在背景查詢，不會卡住畫面。

### 儀器伺服器：群組

- 每台量測節點（電腦）一個群組，列出它下轄的儀器，另有「未歸屬」群組（`labcontrol/remote/groups.py`）：
  - Hub 記錄了歸屬 → 放在那台的群組；
  - 共用但還沒歸屬的網路儀器、只被掃描偵測到的儀器 → 未歸屬；
  - 只有一台設定了 → 那台的群組。
- **移動**：拖曳到群組、右鍵「移到群組」、或工具列「移到群組…」。
  - 目標電腦沒有設定時，會把設定複製過去（節點 `add_instrument`，寫入那台的 `instruments.yaml`）；
  - 然後 Hub 記錄歸屬，其他電腦上連著的會自動中斷；
  - 拖到未歸屬 = 清除歸屬；
  - USB / GPIB 儀器不能用軟體移動。
- 每個群組都有「全部連線 / 全部斷線」，別台節點的群組也可以按。
  別台節點的儀器可以連線 / 中斷，雙擊會開遠端控制視窗。
- **共用但未歸屬的網路儀器不能連線**：會顯示「尚未歸屬，請先移到某個量測節點的群組」。
  Hub 在節點回報時一起回傳 `shared` 清單。
- 儀器回報多了 `options`（可以 JSON 化的設定），Hub 登錄會保存，移動時用來複製設定。

### 外觀

- 共用樣式 `labmonitor/style.py`：
  - 深色：炭灰底、卡片、細框、圓角；
  - 按鈕：藍色主要按鈕、外框按鈕、紅框危險按鈕；
  - 標題 + 灰色副標題。
- Lab Control、儀器伺服器、Monitor 都使用這份樣式。「▶ 開始量測」是主要按鈕。預設為深色。

### 發佈

- `tools/make_release.py` 一次產生三個發佈檔。Monitor 是獨立的 Lab APP 程式資料夾：`main.py`、`labmonitor/`、內附的 `labhub/`、`requirements.txt`（PyQt6、PyYAML）、`.entry`、`.icon`、`.readme`、`.python-version`。

## 變更

- Hub token 預設 `Labqel330`：`docker-compose.yml` 的 `LABHUB_TOKEN`、`settings.yaml remote.token`、Monitor 預設值。
  這組 token 寫在發佈檔裡，拿到程式的人都看得到，請不要和 NAS 或其他帳號共用密碼。

- `docker-compose.yml` 新增 `agent` 服務。

## 上線步驟

1. **NAS：加入控制代理（只需要一次）**，詳細步驟見 `deploy/hub/README.md`「第一次」：
   - 把 `LabControlHub_v0.0.9.zip` 裡的 `labhub/`、`backups/`、`docker-compose.yml` 複製到 `\\100.114.33.20\docker\LabControlHub\`；
   - 如果之前拿掉了 `/releases` 那行的 `#`，新檔也要同樣改；
   - 在 Container Manager 用新的 compose 重新建立專案；
   - 確認 `labcontrol-hub` 和 `labcontrol-hub-agent` 兩個容器都在執行，防火牆允許 8766。
2. 在 Lab APP 發佈 `LabControl` 0.0.9 和新程式 `LabControlMonitor` 0.0.9，各電腦更新 / 安裝。
3. 打開 Monitor →「Hub 控制台」，確認看得到網站狀態與版本。以後更新 Hub 都在這裡操作。
4. 打開儀器伺服器，把「未歸屬」裡的共用儀器（例如 ZNA 192.168.1.11）拖到要用它量測的節點群組。
