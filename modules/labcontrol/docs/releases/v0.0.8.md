# Lab Control 0.0.8

- 發佈日期：2026-09-30
- 類型：功能版本（跨電腦儀器管理、Lab Control Monitor、Hub 線上更新）＋ 量測卡住修正
- Python：3.12
- 前一版：0.0.7

## 摘要（貼到 Lab APP「版本說明」）

- 儀器可以在任何電腦上透過量測節點連線、控制。
- Hub 記錄每台儀器掛在哪台電腦。兩台電腦都連得到的網路儀器（例如 ZNA）要先「拉取」到一台電腦，其他電腦會自動中斷，也連不上。
- 新增「全部連線 / 全部斷線」。
- 新增 Lab Control Monitor（exe）：看所有節點與儀器、遠端控制儀器、直接更新 NAS 上的 Hub。
- 修正：節點在 Hub 很慢時會拖住量測（看起來卡在量測中）。
- 新增卡住偵測：量測太久沒進度時，自動把程式狀態存到 `LAB/logs`。

## 新增

- **儀器登錄**：
  - 每台 Lab Control 回報儀器時附上識別碼：網路儀器用 IP，USB 用廠商 / 產品 / 序號；
  - Hub 記錄每台儀器掛在哪些電腦、目前在哪台連線、首次與最後一次看到的時間；
  - VISA 掃描偵測到、但還沒設定的儀器也會記錄（`GET /api/instruments`）。
- **共用儀器的拉取群組**：
  - 兩台以上電腦設定了同一台網路儀器時，標成「共用，未拉取」；
  - 拉取到某台電腦後，其他電腦連著的會被中斷，之後也連不上，會顯示「目前歸 X 使用」；
  - 量測中的儀器不能被拉走。
  - 可以從三個地方拉取：Monitor、Hub 網頁、Lab Control 儀器伺服器「⇩ 拉取到這台」。
- **全部連線 / 全部斷線**：
  - 用在節點下轄的儀器，可以從 Monitor、Hub 網頁的節點卡片、儀器伺服器操作；
  - 遇到錯誤繼續下一台，最後列出每台的結果；
  - 歸別台的共用儀器會略過，量測中的儀器不會被中斷。
- **遠端控制儀器**：
  - 節點新增這些指令：`describe`（參數表）、`get_all`、`connect` / `disconnect`、`connect_all` / `disconnect_all`、`scan`、`release`；
  - Monitor 的遠端控制視窗可以讀取全部、寫入變更、連線 / 中斷、自動讀取，照樣受 lease 保護。
- **Lab Control Monitor**（`labmonitor/`，只需要 PyQt6）：
  - 分頁：量測節點、儀器、所有電腦、Hub；
  - `deploy\monitor\build_exe.bat` 產生單一 exe；
  - Lab Control 主視窗「設定 ▾ → Lab Control Monitor…」也能開。
- **Hub 線上更新**：
  - Hub 可以從 Lab APP 發佈資料夾，或 Monitor 內附的版本，安裝新版並自己重新啟動；
  - 新版連續兩次啟動失敗，會自動退回；
  - Hub 網頁與 Monitor 都有更新按鈕（`/api/hub`、`/api/hub/update`、`/api/hub/install`、`/api/hub/restart`）。
- **Hub 網頁**：新增儀器表（掛載位置、歸屬、拉取）、節點的全部連線 / 全部斷線 / 掃描按鈕、Hub 版本與更新。
- **卡住偵測**：量測中超過 `run_defaults.stall_warn_s`（預設 120 秒）沒有進度時，把所有執行緒的堆疊存到 `LAB/logs/stall_*.txt`，並在量測訊息顯示路徑。
- **斜坡顯示**：移到起點時顯示目標與剩餘時間；訊息附上目前值與預估分鐘數。

## 修正

- **節點上的量測被 Hub 拖住**：0.0.7 的節點在量測執行緒裡把即時資料上傳到 Hub；上傳時又持有鎖，Hub 一慢（VPN 逾時），每一點都要等。
  現在量測執行緒只把資料排進佇列，由獨立的上傳執行緒送出；Hub 斷線時資料會補送，太久時只丟最舊的曲線。
  測試：Hub 每次回應延遲 1.5 秒時，11 點量測仍在 4 秒內完成。
- **Hub 偶發逾時**：控制端連續 3 次失敗才視為斷線（0.0.7 是 1 次）；逾時從 10 秒延長到 15 秒；狀態列會顯示「回應慢，重試中」。
- 遠端控制時，電源輸出值以 mA 顯示（與儀器控制視窗相同）。

## 上線步驟

1. **Hub 升級（一次）**：把新的 `labhub` 資料夾複製到 `\\100.114.33.20\docker\LabControlHub\`，覆蓋舊的，然後在 Container Manager 重新啟動 `labcontrol-hub`。之後的更新可以在 Monitor 或網頁上完成。
2. 各電腦更新 Lab Control 到 0.0.8。有儀器的電腦開「🛰 量測節點」。
3. 在一台 Windows 電腦執行 `deploy\monitor\build_exe.bat`，產生 `LabControlMonitor.exe`。
4. 在 Monitor 的「儀器」分頁找到「共用，未拉取」的儀器（例如 ZNA 192.168.1.11），拉取到要用它量測的節點。

## 已知限制

- exe 必須在 Windows 上建置（`build_exe.bat`）；開發環境只能驗證打包流程（Linux 版可以正常開啟並連線）。
- 只連到控制端（沒開量測節點）的電腦，儀器會列在登錄中，但不能被遠端控制。
- 0.0.7 回報的量測卡住，還需要那台量測節點的 `LAB/logs/labcontrol.log`（或 0.0.8 產生的 `stall_*.txt`）才能確認實際原因。

## 測試

自動測試全部通過（Python 3.11、3.12）。新增的測試：
- 儀器識別碼；
- 共用儀器登錄、拉取後另一台被中斷與拒絕連線、拉回、量測中不能拉取；
- 全部連線 / 全部斷線；
- describe / get_all / set / scan 回報到登錄；
- Hub 很慢時量測不被拖住；
- 卡住偵測存檔；
- 真的啟動 Hub 程序：從發佈資料夾自我更新、zip 安裝、啟動失敗退回；
- Monitor 視窗：節點、儀器、全部連線、遠端控制寫入。
