# Lab Control 0.0.6

- 發佈日期：2026-09-30
- 類型：功能版本（淺色 / 深色模式）＋ 實機驅動修正
- Python：3.12
- 前一版：0.0.5

## 摘要（貼到 Lab APP「版本說明」）

新增淺色 / 深色模式：工具列右上 🌙 / ☀ 一鍵切換，或「設定 ▾ → 外觀」選淺色 / 深色 / 跟隨系統，所有視窗即時換色，選擇會記在 settings.yaml。
同時依 VNA1（ZNA26）實機驅動測試報告修正：儀器資料格式停在二進位時讀不到頻率軸的問題；儀器上沒建立的 S 參數 trace 在測試中改為略過。

## 新增

- **淺色 / 深色模式**（`labcontrol/apps/qt/theme.py`）
  - 主視窗與儀器伺服器工具列 🌙 / ☀：淺色 ↔ 深色。
  - 「設定 ▾ → 外觀」：☀ 淺色 / 🌙 深色 / 🖥 跟隨系統（Windows 切換深色時自動跟著變；Qt 6.8 起標題列也會變色）。
  - 選擇寫回 `LAB/settings.yaml` 的 `app.theme`（只改這一行，保留其他內容與註解）；`python main.py --theme dark` 只影響這次開啟。
  - 換色範圍：Qt 調色盤（所有視窗、對話框、表格、輸入框）、流程圖（背景格點、節點、連線、迴圈框、連接點）、
    即時監控與 Step 預覽與 VNA trace 的 pyqtgraph 圖表、狀態文字（錯誤 / 警告 / 完成）、提示框（半透明底色，兩種模式都適用）。
  - 深色模式下方塊顏色（`settings.yaml editor.colors`）太暗時自動調亮文字與線條，設定值不用改。
  - 「重新載入設定」也會套用 `app.theme`。
- **開發者**：UI 顏色改用語意名稱 `theme.c("err")`、`theme.qc("text")`、`theme.tint("ok")`；自己畫的元件用
  `theme.on_change(obj, fn)` 登記重繪。新增顏色時 `LIGHT`、`DARK` 兩個表都要加（有測試檢查）。

## 修正（依實機報告）

- **R&S ZNA 讀 x 軸失敗**：VNA1 報告 `CALC1:DATA:STIM? → 'ascii' codec can't decode byte 0x95`。
  原因是儀器的資料格式（`FORMat`，全域設定）停在 `REAL`（其他程式或前面板設定的），驅動只在量測時才送 `FORM`。
  改為每次讀數值陣列（x 軸、trace）前都先送 `FORM ASC`（`data_format: real64` 時送 `FORM REAL,64` + `FORM:BORD SWAP`），
  並與選 trace 一起鎖住，不會被其他執行緒插入指令。
- **驅動測試的 trace 項目**：儀器上沒建立的 trace（報告中的 S11 / S12 / S22）改為「– 略過」並說明如何建立；
  真的讀取失敗才是 ✖（以前一律是 ⚠，會把驅動錯誤藏起來）。
- 以 GS200（DC1）實機報告確認：讀取、寫回相同值、小幅度輸出全部通過，不需修改。

## 上機確認

1. 更新後在儀器伺服器對 VNA1 再跑一次「驅動測試」（勾「量測一次」）：S21 x 軸應為 ✔ 10001 點，S11 / S12 / S22 為「略過」。
2. 如果要量 S11 等其他參數：在 ZNA 上建立 trace，或在 `instruments.yaml` 的 VNA1 設 `auto_create_trace: true`，
   或把 `traces:` 改成實際要量的清單（例如 `traces: [S21]`）。

## 測試

- 自動測試 84 項全部通過（Python 3.11、3.12），新增：
  - 深淺色切換：主視窗與儀器伺服器同時開著即時切換、調色盤 / 流程圖背景 / 圖表背景換色、寫回 settings.yaml 並保留註解、
    設定值錯誤時退回淺色、跟隨系統；兩個顏色表名稱一致。
  - ZNA：模擬儀器格式停在 REAL 時 x 軸與量測仍正確；x 軸讀取前送 `FORM ASC`；沒建立的 trace 標為略過。

## 已知限制

- 開發環境（Linux 無螢幕 offscreen、PyQt6 6.11 + pyqtgraph 0.14）連續建立大量視窗的自動測試，偶爾（約 1/15 次）
  在 pyqtgraph 建立圖表時 Segmentation fault；0.0.5 同樣存在、比率相同，與深色模式無關。
  本版順便把 Qt 前端所有背景執行緒改成在 GUI 執行緒釋放視窗物件（`labcontrol/apps/qt/worker.py start_thread`），
  但測試中的偶發當機仍在，原因尚未確定。實機使用尚未遇到；若 Lab Control 突然關閉，請回報 `LAB/logs/labcontrol.log` 與當時的操作。
