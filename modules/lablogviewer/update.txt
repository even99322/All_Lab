LabLogViewer v0.17B - Windows Static Compatibility Audit
Date: 2026-09-25

Scope
-----
Targeted source inspection only. No Windows VM, Wine, remote Windows,
Windows GUI execution, Windows packaging, network request, or full regression
run was performed. This audit does not establish native Windows compatibility.

Areas inspected
---------------
Production paths and temporary files; persistent JSON/text encoding; application
theme, Follow System, scientific plot and export appearance; Settings > Appearance
> Advanced QAction/QMenu construction; open/save/export dialogs; clipboard and
drag-to-share MIME/file URLs; Online Paper Library launcher; shell/process calls;
shortcuts; session and tag persistence; and obvious 3D/OpenGL platform assumptions.

Findings by severity
--------------------
CRITICAL: None found by static inspection.
HIGH: None found by static inspection.
MEDIUM: Rename reserves the destination with os.link() before unlinking the
old name (app/core/data_rename.py). This preserves no-overwrite behavior on
filesystems that support hard links, but Rename may fail on Windows removable
or network filesystems without hard-link support. No change made: replacing
the transaction requires behavioral testing and is outside this audit.
LOW: Follow System depends on Qt reporting colorScheme()/colorSchemeChanged;
the code falls back to the initial application palette if the API is unavailable.
Runtime response to Windows appearance changes remains unverified.

SAFE / INTENTIONAL
------------------
- External JSON uses explicit UTF-8 reads/writes, including tags.json and
  settings.json; no CP950-dependent persistent JSON decoding was found.
- POSIX directory fsync is explicitly skipped on Windows (os.name != "nt").
- Settings > Appearance > Advanced uses Qt QAction/QMenu APIs; application,
  scientific plot, and export appearance states are persisted independently.
- Online Paper Library uses QDesktopServices.openUrl(QUrl(...)); its URL was
  not opened or contacted during this audit.
- Drag-to-share uses QMimeData and QUrl.fromLocalFile(Path), not a Finder-only
  command. Clipboard uses Qt APIs. Dialogs use QFileDialog.
- The one platform-dependent shortcut uses Meta on macOS and Ctrl elsewhere;
  standard Copy/Save shortcuts use QKeySequence.StandardKey.
- The 3D backend probes for an OpenGL context before constructing Q3DSurface;
  actual Windows GPU/driver behavior is not established by static inspection.
- No production os.system, subprocess, shell=True, AppleScript, osascript,
  pbcopy/pbpaste, defaults, xattr, or hard-coded /Users or /Applications path
  was found in the targeted production search.

Changes and checks
------------------
Files modified: update.txt only. No application code or scientific data changed.
Small fixes applied: none.
Checks: targeted ripgrep searches and source review. No tests rerun; the prior
v0.17B full suite was 773 passed, 3 skipped, 31 warnings, and 118 HDF5/H5
SHA-256 values were unchanged. Those are prior results, not audit reruns.

Windows native validation: NOT PERFORMED.
Windows packaging validation: NOT PERFORMED.

Later validation
----------------

Reference, license, and implementation

Architecture and coverage
-------------------------
app/gui/glass.py provides GlassRenderer, GlassToolSurface and GlassToolBar.
Browser uses GlassToolSurface behind its existing three toolbar segments.
Viewer uses GlassToolBar behind its existing QAction/QToolButton row.
The v0.17C IconManager-equivalent app/icons.py remains independent and paints
the existing SVG/PNG icons as sharp foreground; actions, callbacks, shortcuts,
tooltips and accessibility labels remain owned by their original controls.
Analysis controls, scientific plots, tables, colorbars, 3D viewport, and
fitting/numerical code intentionally receive no Glass.

Material and lifecycle
----------------------
The material samples only the in-app parent background using QWidget.render
without drawing children. It reduces the backdrop for frosting, computes a
small edge displacement/refraction with NumPy, applies theme-specific tint,
and paints a subtle sheen/rim. Foreground children are never blurred or
distorted. The raster is HiDPI-aware using devicePixelRatioF and QImage DPR.
The optical image is cached and invalidated on show, resize and theme change;
the timer coalesces refreshes. Idle paint uses the cached image, not another
data transformation or capture. Browser Safe Recovery uses the fallback.
LABLOGVIEWER_DISABLE_GLASS=1 disables optical processing globally. Rendering
exceptions also fall back to the same geometry-preserving solid material.
No desktop capture or screen-recording permission is required.

Lag: root cause was the v0.17C icon engine, not the glass
----------------------------------------------------------
- Measured: glass refresh ~8 ms, only on show/resize/theme; 0 at idle.
- Qt calls QIconEngine.isNull() on every paint/size-hint pass. app/icons.py
  re-parsed the SVG with a new QSvgRenderer on every call. A QTreeWidget with
  ResizeToContents columns re-measures every row whenever one row's icon
  changes, so the Trace Manager (one eye icon per trace) was quadratic: the
  855-trace 0828 RSMEP_1 file made 362,598 isNull calls (20 s) before the
  window finished. This is also the "pre-existing" hang of
  test_toolbar_trace_manager_popouts_and_resizable_panes noted above.
- Fix (app/icons.py): SVG validity cached by content, recolored
  QSvgRenderers cached, one shared QIcon per semantic name (colors are still
  resolved at paint time, so Light/Dark switching is unchanged).
- Fix (app/gui/main_window.py _refresh_multi_trace_panel): ResizeToContents
  is suspended during the bulk update and restored once; new rows are built
  before insertion; rows whose visible/active/reference state did not change
  are skipped. The hanging test now completes.

Liquid Glass rework (app/gui/glass.py)
--------------------------------------
- Why v0.17D looked weak: it refracted only the uniform window background, so
  the result was a flat gradient box, and only a 2.5 px edge offset of PyGlass
  was used.
- Now: PySide6 port of PyGlass GlassKernel/GlassMaterial/paint_glass (MIT,
  see docs/third_party_pyglass.txt), retuned for ~40 px capsules (bevel
  clamped below half the capsule height). Snell refraction with chromatic
  dispersion, Schlick-Fresnel environment reflection (bright top rim), a
  spectral rim line, frost blur + milky haze, soft shadow, tint, sheen and
  hairline. Light and Dark have separate styles.
- Capsules: controls that sit together share one pill. Browser: Open/Reload |
  Star/Tag/Retrieve/Back | glass dials | Appearance/De-background. Viewer:
  separators split the toolbar into pills; overlapping pills are split at the
  midpoint.
- Backdrop: the parent's background plus sibling widgets inside the
  refraction margin (e.g. the workspace just under the Browser toolbar),
  never the host or its own buttons.
- Cost: kernels cached per capsule size/thickness; a cached refresh measured
  7-14 ms (offscreen) and runs only on show/resize/theme/dial change or when
  controls move (settles after 120 ms, reusing cached pills meanwhile).
  Idle cost is zero. Frost never rebuilds a kernel.
- Fallback unchanged in intent: LABLOGVIEWER_DISABLE_GLASS=1, Safe Recovery,
  or any optical exception paints a vector pill with the same geometry.

Glass dials (Browser toolbar, right segment)
--------------------------------------------
- Two compact sliders, Thickness and Frost (0-100), in the style of the

============================================================
Date: 2026-09-25

Implemented
-----------
- Browser measurement rows use Qt's normal left-drag threshold. Dragging onto
  the Quick Preview transfer target sends one selected log to the configured
  IP/host and port. Click, Star and double-click Viewer behavior remain.
- The Browser can start/stop a TCP receiver. Sending runs on QThread and
  displays preparing, connecting, byte progress, completed or failed status.
  Receiving runs on a background thread and stores externally under
  ~/.lablogviewer/received/; source HDF5 is read-only.
- app/core/measurement_transfer.py serializes existing Experiment output,
  not raw HDF5 fields. ZIP contains UTF-8 manifest plus .npy numeric arrays
  with allow_pickle=False. Channel identity, units, logical dimensions,
  sweep-axis order/values, scalar/vector flags, relation metadata and raw
  real/complex data are retained. All actually present Sij (i,j=1..4) and
  generic channels use the same path; no derived magnitude/phase duplication.
- app/core/measurement_transport.py protocol v1 frames byte length and SHA-256,
  checks corruption/incomplete transfer and validates the archive before
  atomic storage. No executable object deserialization or sender-supplied path.
- Receiver reconstruction API: load_measurement(), get_data(),
  list_dimensions(), get_full_nd_array(). Direct Viewer opening of a received
  archive is intentionally deferred; this is not a full Network Workspace.

Flux / Empty / Function / Scalar regression
-----------------------------------------
The requested /mnt/data path is absent on this Mac, but the exact real file
exists at ../Data/CPAEP/Data_0908/0908 X2 Flux-dep.hdf5. Existing Parser
interprets it as Frequency 10001 x DC supply - 3 - Current 399, with complex
VNA - S21 shape (10001,399). DC supply - 4 - Current retains its relation
flag and equation x. A real socket transfer and receiver round-trip compared
the entire complex array, logical axes and relation metadata. Empty was never
interpreted independently in transfer. Real S31 was also tested from
0826 LRCPAEP @4.782GHz.hdf5; all 16 Sij names were synthetic-tested.

v0.19A - NETWORK WORKSPACE (HOST / CLIENT)
============================================================
Date: 2026-09-26
Folder operation: NEW folder LabLogViewer_v0.19A copied from v0.18D
(v0.18D and LabLogViewer_v0.18D.zip unchanged). __version__ = "0.19A".

User decisions
--------------
- Client follows the Host (mirror, view only; the whole Client app is
  view-only while connected; only the Network panel and Leave work).
- Join code only (6 digits, HMAC challenge; the code never crosses the
  network; 5 wrong codes lock that address for 60 s).
- Data source: a copy on the Client's "shared data folders" (same size and
  SHA-256, e.g. shared storage) is used first; otherwise the Host sends it.
- Permanent copy only when the Host sends it; otherwise received data lives
  only in memory and is dropped on disconnect.
- Quality minimum: RTT <= 200 ms and >= 1 MB/s (grades excellent / good /
  fair / too poor; updated every 2 s on both sides).
- Viewer (2nd window) and YIG Analysis are synced; 3D is not.
- Entry at the very top of the Browser (status bar + panel).

Design
------
- app/network/protocol.py: framed protocol (magic, version, CRC32,
  optional zlib, size limits); values are JSON + numeric numpy arrays only.
- app/network/remote_data.py: the Host sends the parser's Unified Data Model
  as values (channels, active step axes, vector traces incl. every Sij that
  exists, Empty / Function / Scalar semantics as parsed, metadata); the
  Client rebuilds the same Experiment around a RemoteReader. Existing
  Viewer / Transform / YIG code works unchanged; the GUI never uses h5py.
  No Host absolute path is sent (file name / database-relative hint only).
- host.py / client.py / transport.py: background threads; control frames
  before bulk; 1 MB chunks with SHA-256; reconnect (1, 2, 4 s) and resume
  of interrupted transfers; heartbeats every 2 s; 8 s idle timeout; Host
  serves only datasets of the shared measurement.
- discovery.py: UDP query / answer (name, session, clients, port).
- workspace.py: HostPublisher (follows the Viewer in use; publishes view
  state + the raw reads it needed, 2D zoom, YIG figures as data, pen / laser
  strokes); ClientMirror (prefetch in background, then apply; mirror
  Viewer with throwaway stores; YIG mirror; ink); view-only input filter.
- figure_sync.py / yig_snapshot.py / yig_mirror.py: YIG figures as data
  (lines <= 2000 points with peaks kept, images <= 480 px), tables as text;
  only redrawn figures are resent. No code is ever sent.
- Settings: network user name (asked on first use, any language),
  session name, shared data folders.

Virtual acceptance (127.0.0.1 only, sandbox HOME inside the project;
no LAN, no NAS; LABLOGVIEWER_NET_SANDBOX=1)
-----------------------------------------------------------------------

  local (3 files do not parse locally either).
- tests/test_v019a_network.py (17): protocol checksum / version / no objects;
  identical data incl. multi-Sij (S11 S12 S21 S22 S31 S42) and Function
  dimension files; wrong code; 5-client limit; discovery on loopback;
  poor quality refused (260 ms latency, 0.3 MB/s); cut mid-transfer ->
  reconnect + resume + checksum; silent Host -> timeout -> disconnected;
  Host unavailable; Host stop -> Clients disconnected; permanent copy

- tests/test_v019a_network_gui.py: real Host and Client processes: 1D mirror

v1.0.3 - NAS WRITES, SAME-NAME QUESTION, RE-LINK THAT MERGES (folder LabLogViewer_v1.0.3, copied from v1.01)
Version numbers now have three parts like the Lab APP release tags (Lab APP published v1.01 as v1.0.2).
app_update.version_key reads two-part 1.x names as 1.0.x, so 1.01 < 1.0.2 < 1.0.3 < 1.0.10.
Date: 2026-09-29

Why
---
- De-background output on the lab NAS failed: "Could not safely publish without replacing an
  existing file: [Errno 45] Operation not supported". The finished file is published with a
  hard link (os.link, atomic and never overwrites); SMB shares have no hard links.
- Re-link on the NAS left most records behind ("Kept unchanged (the new path already had
  records)"): opening the new location had already created automatic tag states for every file,
  and any record at the new path made the old one be skipped. Stars/tags were also filed under
  the chosen folder rather than the database open in the Browser.
- The user asked that every save next to an existing file of the same name ask first:
  Overwrite or Keep Both.

Changes
-------
- app/core/hdf5_processing_writer.py: publish_temporary falls back, when os.link fails with
  any OSError other than FileExistsError, to "check the name is free, then os.rename" (same
  pattern data_rename.py already used). An existing output is never replaced implicitly.
- app/core/record_merge.py (new): merge_record(file, key, existing, incoming) -> (value, conflict).
  Program-made records give way (automatic tag states, view snapshots, empty Marks, fingerprints
  kept from the new file); user tags are joined (Flux vs BG = conflict), comments both kept,
  named views/overlays/axis presets with the same name kept as "name (2)". Only two different
  user records that cannot be combined are a conflict.
- app/core/relink.py: _rewrite() shared by preview_conflicts() (dry run) and apply(prefer_old=...);
  records at both paths are merged; stars need no comparison; several database roots (Browser's
  open database first, then the chosen folder); YIG session replace uses os.replace.
  New match_by_prefix() (old folder -> new folder, name + size only, reads nothing) and
  suggest_old_prefixes() (the folder the missing files share and each folder above it).
- app/gui/relink_dialog.py: "Old folder (quick, by path)" + Match by Path; before applying, real
  conflicts are listed and the user chooses Overwrite with Old Records / Keep Current Records.
- app/core/migrate.py (Data Transfer): uses merge_record for its keyed merges (automatic tags are
  no longer conflicts); _merge_tag_lists now merges tag_categories as {tag: category} (it treated
  them as {category: [tags]} and could add empty lists).
- app/gui/save_target.py (new): numbered(), ask_existing() (Overwrite / Keep Both / Cancel,
  Keep Both default), ask_keep_both() (Keep Both / Cancel), confirm_save().
- app/localization/manager.py: the wrapper every QFileDialog.getSaveFileName already passes
  through now sets DontConfirmOverwrite and asks the question above (adds the selected type's
  extension first, also for names like "4.9~5.1GHz X2" whose Path suffix is not an extension).
- De-background output question: Overwrite / Keep Both / Choose Another... / Cancel; a path
  already confirmed in the save dialog is not asked again. Data export likewise.
