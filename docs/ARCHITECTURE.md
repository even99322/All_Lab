# 架構

## 一、元件

| 元件 | 在哪裡 | 做什麼 | 依賴 |
|---|---|---|---|
| 大程式網站 `portal` | NAS（Docker，:8090） | 唯一入口：登入、權限、共用標籤、數據登錄、事件、模塊發佈、量測中繼、網頁 | 標準函式庫 |
| 論文庫 `paperlib` | NAS（:8080） | 帳號與站長、論文、論文標籤（原程式，沒有修改） | FastAPI 等 |
| 量測中繼站 `labhub` | NAS（:8765） | 量測指令、即時資料、量測檔（原 Lab Control Hub） | 標準函式庫 |
| 更新代理 `agent` | NAS（:8767） | 各服務的更新、備份、自動回復、日誌 | 標準函式庫＋docker.sock |
| 通信模塊 `labcomm` | 每台電腦（大程式自動安裝） | 模塊與大程式、模塊與模塊之間的所有通信 | 標準函式庫（讀寫 HDF5 用 h5py） |
| 桌面大程式 `launcher` | Windows／macOS | 登入、安裝／更新／開啟模塊、轉交動作 | PySide6 |
| 量測模塊 `labcontrol` | 量測電腦 | 儀器控制、流程圖量測、量測節點 | PyQt6 等 |
| 讀檔模塊 `lablogviewer` | 任何電腦 | 讀 Labber／HDF5、分析、擬合、3D | PySide6 等 |
| 監控程式 `monitor` | 站長的電腦 | 監控、通知、服務更新、模塊發佈、權限 | PySide6 |

設計原則：

1. **模塊之間不直接 import**。量測模塊不知道讀檔模塊的程式，反之亦然；彼此只透過 labcomm 的「動作」（`open_file`、`apply_scheme`、`show_papers`）與大程式 API 溝通。
2. **每個模塊各自版本與發佈**。`module.json` 是唯一規格（見 MODULES.md）。更新量測模塊不會動到讀檔模塊或通信模塊。
3. **原程式盡量不改**。論文庫完全沒改；Lab Control 與 LabLogViewer 只加了一個整合檔（`integrations/qel.py`、`interfaces/qel.py`）和幾行接線，沒有 labcomm 時照原本方式運作。
4. **NAS 是唯一的中繼**。所有網路通信都經大程式網站：使用者用自己的帳號，Hub 的共用 token 只留在 NAS 上。

## 二、帳號與權限

- 登入：大程式把帳密轉給論文庫 `/api/auth/login`（帶上使用者真正的 IP，論文庫的登入鎖定照樣有效），拿到論文庫 session 後由大程式保存，之後代表這個人查論文。兩步驟驗證照用。
- **站長**＝論文庫的站長（`owner`）；還沒有站長時，由論文庫管理員代理（與論文庫的規則相同）。不另外分角色。
- 站長在網頁「管理 → 使用者與權限」或監控程式「使用者」：每個人、每個模塊一個開關（論文模塊、量測模塊、讀檔模塊），以及「可以登入大程式」。新帳號的預設權限也可以改（預設：論文、讀檔開；量測關，因為會控制硬體）。
- 註冊：大程式登入頁「申請註冊」轉給論文庫，由站長在論文庫審核（與原本流程相同）。
- 論文庫停用帳號、改密碼登出 → 大程式每 10 分鐘向論文庫確認一次，session 跟著失效。
- 網頁：token 只放在 HttpOnly cookie，修改資料的請求必須帶 `X-QEL: 1`（防 CSRF）；桌面程式用 `Authorization: Bearer`。
- 單一登入：網頁登入時一併設定論文庫的 cookie（同主機不同埠共用；外網子網域用 `QEL_COOKIE_DOMAIN`）。桌面程式開網頁用一次性登入票（60 秒、只能用一次），token 不會出現在網址上。

## 三、資料流程

### 1. 量測好的數據 → 讀檔模塊

```
Lab Control 存檔 ──(data.exported 事件)──▶ integrations/qel.py
   ├─ 寫進數據檔：qel/scheme（量測方案）、qel/meta（標籤、來源）——之後不再改檔，內容指紋才會一致
   ├─ 登錄到大程式 POST /api/v1/datasets（名稱、路徑、內容指紋、標籤、方案）→ 事件 dataset.created
   └─ 讀檔模塊開著 → 本機傳遞 open_file → LabLogViewer 開一個 Viewer
量測節點上傳到 Hub ──(data.uploaded)──▶ 更新登錄（hub_file）→ 網頁、手機、其他電腦都能下載
```

`settings.yaml` 的 `qel:` 可以關掉任一步（`embed_scheme`、`register_datasets`、`open_in_viewer: running|always|never`）。

### 2. 讀檔模塊 → 量測模塊（套用設置）

- 把 Browser 裡的數據**拖到 Lab Control 視窗**（拖曳帶檔案網址），或 Interfaces → Measurement，或拖到桌面大程式的量測模塊卡片。
- Lab Control 讀回數據檔的方案：`qel/scheme` → Lab Control 原生 HDF5 的 metadata → 同一天 `_raw/` 的原生檔。舊檔沒有方案時會說明原因。
- 量測模塊沒開時，labcomm 請桌面大程式先開啟它再轉交（`local.deliver`）。

### 3. 標籤 → 論文

- 共用標籤存在大程式：分類（專案、階段、板子設計、數據分析、量測、論文主題、其他）、顏色、說明、別名。
- 一個標籤對應的論文＝**手動連結的論文**＋**論文庫裡標了同名標籤的論文**（自動）。
- 數據 → 依它的每個標籤列出論文，點了直接開論文庫的那篇（`#/p/<id>`）；標籤也可以開論文庫的標籤頁（`#/t/<名稱>`）。
- 量測模塊的 Tags 欄位提示共用標籤；讀檔模塊啟動時把共用標籤加進 Tags；舊寫法（例如 `best_data`）用別名統一。

### 4. 跨電腦

`POST /api/v1/handoff` 把動作送給**同一個使用者**其他電腦上的桌面大程式，它轉給本機開著的模塊（例如在手機網頁按「在電腦上開啟」）。

## 四、更新

| 對象 | 怎麼更新 | 失敗時 |
|---|---|---|
| 桌面模塊（量測、讀檔、通信、大程式本體、監控程式） | 站長發佈 zip（網頁或監控程式）→ 每台電腦的大程式提示更新，各模塊各自一個版本資料夾與 Python 環境 | 「換回上一版」（保留 2 個版本） |
| NAS 服務（大程式網站、論文庫、Hub、更新代理） | 監控程式「服務更新」選 zip → 代理：檢查 → 停止 → 備份 → 換程式 → 重建 → 啟動 → 確認版本 | 自動換回舊版；也可以「回到這版」 |

已發佈的版本不能覆寫（與 Lab APP 的規則相同），有問題就發佈下一個版本號或撤回。

## 五、監控

監控程式每 10 秒讀一次：大程式 `/api/v1/health`（論文庫、Hub 的狀態與回應時間、流量、錯誤、NAS 空間、線上人數）與更新代理（每個容器的狀態、執行中與磁碟上的程式版本）。異常（服務離線、容器停止、程式已換但沒重啟、空間不足、錯誤變多）會跳系統通知，恢復時也會通知。

大程式網站本身壞掉時，監控程式可以用更新代理的**緊急 token** 登入，只管理服務（重新啟動、回到備份）。

## 六、平台

- 網頁：原生 JavaScript，不需要編譯；響應式版面，手機寬度沒有橫向捲動；PWA 可安裝（Android「安裝應用程式」、iOS「加入主畫面」）。
- 桌面：Python 3.12＋Qt（Windows、macOS）。量測模塊用 PyQt6、其他用 PySide6，彼此是不同程序，不衝突。
- 手機上不能控制儀器編輯方案（需要桌面版），但可以看量測進度、暫停／停止、看數據與論文、管理權限。

## 七、安全注意事項

- 大程式的 session token 只存雜湊；但為了代表使用者查論文，**論文庫的 session 會存在 `portal/data/portal.db`**。這個資料夾的權限比照論文庫的 `data/`（只有 NAS 管理員能讀）。
- Hub 的共用 token 只寫在 NAS 的 `docker-compose.yml`；使用者、手機、網頁都不需要知道。量測電腦（節點）仍用它直接連 Hub。
- 不要把 Hub（8765）與更新代理（8767）開到外網。更新代理掛載了 `docker.sock`，只接受站長登入或緊急 token。
- 大程式預設信任 `X-Forwarded-For`（與論文庫的 `--forwarded-allow-ips *` 相同），論文庫的登入鎖定才看得到真正的來源 IP。若把大程式直接開到外網（沒有經過 Cloudflare 等反向代理），設 `QEL_TRUST_PROXY=0`。
- 數據事件只送給有量測、讀檔或論文模塊的人；跨電腦傳遞（handoff）只送給本人。
